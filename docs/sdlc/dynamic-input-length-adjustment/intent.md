# Intent：输入框 / 编辑框自适应高度（支持多行）

> 状态：待确认
> 日期：2026-10-28

## 当前问题

- 添加待办的输入框（`#todo-input`）和编辑待办的输入框（`.todo-edit-input`）都是固定高度的单行 `<input type="text">`（36px）。
- 内容一旦稍长，输入框内只能横向滚动，看不到全貌，打字时体验差。
- 列表展示区（`.todo-text`）本来就会自动换行，所以痛点集中在**输入和编辑**环节，而不是展示环节。

## 期望结果

- 输入框与编辑框改为**自适应高度**：随内容行数增高，上限约 4 行（~100px），超出上限后框内出现垂直滚动。
- 待办内容**允许换行**：`Enter` 提交，`Shift + Enter` 换行；编辑框行为一致。
- 换行在列表展示中保留（展示需按换行渲染，而非折叠成空格）。
- 输入框 placeholder 增加「Shift+Enter 换行」提示。

## 受影响系统

| 范围 | 说明 |
|------|------|
| `src/index.html` | 添加输入框元素形态（`<input>` → `<textarea>`） |
| `src/assets/app.js` | 输入事件（Enter/Shift+Enter）、编辑框创建逻辑、渲染时换行保留 |
| `src/assets/style.css` | 自适应高度样式、上限与滚动、换行渲染 |
| 后端（Rust / 存储） | **无改动**。存储为纯字符串，换行符无数据层障碍 |
| 交互语义 | Enter/Shift+Enter 分工；自适应高度计算逻辑（添加框与编辑框复用） |

## 数据 / 技术约束

- 后端 `add_todo` / `edit_todo` 接收纯字符串，无需改接口或数据格式。
- 窗口为便签形态（默认 320×480，最小 280×300）；窗口较矮时已有紧凑布局（`max-height: 350px` 媒体查询），输入框上限高度需与之兼容。
- `<input>` 换 `<textarea>` 需处理原生默认行为（自动补全、拼写检查、resize 手柄等）。
- 编辑框是运行时动态创建的 DOM，自适应逻辑必须可复用，不能写死在两处。

## 明确不做的事

- 不新增字符数上限或字数显示。
- 不支持富文本 / Markdown。
- 不改窗口默认尺寸与整体布局。
- 不做 Enter/Shift+Enter 行为的用户可配置（本次固定该行为）。
- 不动拖拽排序、勾选完成、删除等既有逻辑。
